# Agent Note: MCP 配置所有权与增量加载

Status: implemented — 手动 MCP 定义属于管理插件的实时配置。

## Problem

自定义 server 映射并不等于 DSH 的可加载 MCP 连接。配置编辑器修改已有条目，不提供通用的配置树节点创建方法。把整个管理插件重挂载会影响其 RPC、Runtime Skill 和已创建连接。

## Decision

主页面使用独立的新增表单，分别收集 stdio 和 HTTP 定义。`mcp.add` 仅允许 Profile 全局写入，并复用运行版本及接口闸门。Host 通过当前 Fiber 定位配置条目，在 `configEditor.edit` 回调中检查取消和同名冲突，保留其他字段。高级映射拒绝修改管理插件自身条目。失败项显示限定诊断，`mcp.retry` 在全局写闸门内只处理本地失败项，不重连健康项；单项清理失败保留可重试记录，不阻断其他连接。

`managedServers` 是 Schemastery volatile 字段。Loader 更新引用并发送本 Fiber 的 `loader/volatile-update` 后，串行同步按原始定义比较连接：未变化项保留实例，变化项释放自身子 Fiber 后重建。模块异步加载完成后重查当前定义；过期定义和卸载后的异步工作不能创建新连接。官方 MCP Client 拥有传输、工具注册及重连机制，本插件仅拥有配置与其创建的子实例。

配置保存环境变量引用，不保存解析后的环境或请求头值。标准目录返回白名单摘要，不返回命令、地址、参数或原值。HTTP 地址不支持内嵌凭据、查询参数和片段；需要认证时使用请求头环境变量引用。

## Alternatives considered

- 拼接 Profile YAML 创建原生行：绕开官方配置事务，增加并发覆盖和错误配置的风险。
- 把 server 定义放在普通字段：配置变化会导致整个管理插件重挂载，影响已有连接与服务。
- 自己实现 MCP 传输和工具注册：重复官方桥接器的协议与生命周期维护。

## Acceptance criteria

stdio/HTTP 表单不要求自定义映射路径即可提交。重复名称、缺少引用变量、未知版本、非全局视图和排队期间取消均不产生保存。并发同名请求只有一个成功。添加其他 server 时已有实例不重连；恢复配置可加载声明，插件卸载可释放全部所属实例。异步等待期间失效的定义不会启动。

## Consequences

保存成功与连接成功是不同事实；返回 `saved` 和未知连接状态，不承诺远端可用。隔离桥接样本和真实 volatile 更新回归不代替目标桌面端的官方桥接器、实际命令与 HTTP 传输验收。新增配置不会自动安装 server 程序；初次安装插件与新增连接的生命周期分别处理。
